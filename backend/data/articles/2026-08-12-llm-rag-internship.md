## 背景

去年暑期，我在南京拓尔思智能系统有限公司做项目实习生，方向是**大模型应用开发**——主要基于字节的 Coze 平台，为不同业务场景搭建 AI 应用。这也是我第一次真正把大模型用到生产环境里，收获不少。

## Coze 平台能做什么

Coze 是一个低代码的智能体开发平台，把大模型应用需要的零件都准备好了：

- **工作流编排**：把「意图判断 → 知识检索 → 生成回复」这类流程可视化串联起来，不用写太多胶水代码。
- **知识库**：上传文档后平台负责切分、向量化，直接提供检索能力。
- **插件与工具调用**：挂上天气、搜索、数据库查询等工具，让模型能动手做事。
- **变量与记忆**：跨轮对话保存上下文。

对想快速验证一个 AI 应用想法的场景，Coze 这类平台能省掉大量基础设施工作，把精力聚焦在**业务逻辑和效果调优**上。

## 一个 RAG 应用从 0 到 1

实习里花心思最多的是 RAG 类应用。一个完整流程大概是这样的：

### 1. 需求与文档梳理

先搞清楚两个问题：**用户会问什么**、**答案藏在哪些文档里**。这一步决定了知识库怎么搭——是手册类的结构化内容，还是散落的 FAQ，还是长文档？

### 2. 知识库准备

- **文档清洗**：把 PDF、Word 里的页眉页脚、水印、广告位清理掉，不然检索会撞上噪音。
- **切片策略**：根据文档结构（章节、段落）切，而不是一刀切固定长度——切太碎丢上下文，切太大混进噪音。长表格、列表要特殊处理。
- **切片后自检**：随机抽查切片，确认语义完整、没有乱码和截断。

### 3. 工作流搭建

用 Coze 的工作流把链路串起来：**意图判断 → 知识检索 → 上下文组装 → 生成回答 → 结构化输出**。检索不到就明确让模型说"不在知识范围内"，而不是硬编。

### 4. 提示词打磨

- 人设写具体：角色、语气、输出格式都说清楚。
- 给 2~3 个**少样本示例（Few-shot）**，比写一大段规则描述管用得多。
- 让模型按 JSON 返回，方便程序解析和后续判断。

### 5. 评估迭代

这是最关键也最容易被跳过的一步。做法：

- 准备一批**固定测试用例**，覆盖正常问题、边界问题（空输入、超大输入、不在知识库的问题）。
- 每次改提示词或切片策略后，统一跑一遍，把回答**一条条打分**（准确性、是否有引用、是否崩坏），记到表里对比。
- 靠这一套，把"感觉变好了"变成"数字证明变好了"。

### 6. 上线与监控

上线后关注两类信号：**用户问什么**（验证当初的需求假设）、**答得怎么样**（收集反馈继续迭代）。AI 应用上线不是终点，是一轮一轮迭代的开始。

## 工程上的坑

- **幻觉**：模型生成的内容不一定有据可依，检索不到的也要强答。解决靠「只依据检索内容回答 + 加引用」双管齐下。
- **成本与延迟**：长 Prompt 意味着更多 Token 和更慢的响应。要在召回量和生成质量之间找平衡，能用小模型跑的分类任务就别用大模型。
- **知识库更新**：文档一改，旧切片就成了"过期知识"。要建立版本管理，改完重新切分，别让用户查到一个过期的答案。
- **边界兜底**：空输入、超长输入、多轮追问没检索到东西，这些情况都要在提示词和工作流里提前设计好，不然一崩就是一片。

## 收获

实习结束拿了「优秀实习生」的称号，但更值钱的是把学校里学到的 RAG 概念真正落地了一遍：知识库怎么切、检索怎么评、提示词怎么调、上线怎么迭代，全流程走了一遍。后来毕业设计做金融文档问答系统，很多经验都是从这段实习带过去的——比如"评估不能靠感觉，要有固定测试集"这条，直接变成了毕设评测模块的设计原则。
