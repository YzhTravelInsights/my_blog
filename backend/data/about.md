### 1. 基于检索增强的金融文档问答系统（毕业设计）

**技术栈**：Python、FAISS、MongoDB、Neo4j、DeepSeek、vLLM、Gradio、FastAPI

**背景**：上市公司年报平均两三百页，含大量专业术语、复杂表格和结构化信息。大模型直接回答有三大硬伤：幻觉（编造不存在的数字）、时效性局限（拿不到最新财报）、不可追溯（答案没出处，不满足金融监管"谁回答、谁负责"）。毕设目标就是：**让基于年报的问答既准确又带证据链**。

**具体做了什么**：

*文档解析模块*
- 用 `PyMuPDF`（fitz）抽取 PDF 的文本和表格（`find_tables()` 直接拿到带坐标的表格结构）。
- **表格转 JSON**：把二维表格转换成带表头、表尾、字段类型等元信息的结构化 JSON，而不是扁平化成纯文本——保住行列对应关系，这是数值问答不出错的关键。
- 处理两个难点：嵌套表的逐层解析、跨页表格按"页码关联 + 内容连续性检测"合并。
- 从文本和表格中抽取「公司—指标—时间—数值」四元组（如"安靠智电—营收—2019—8.05亿"），为知识图谱打底。
- 每个片段都带上**来源文档、页码、坐标**等溯源标记。

*知识库构建模块*
- **文本向量库**：用 `sentence-transformers` 加载 `bge-large-zh-v1.5`（1024 维）生成章节级文本块向量，存入 FAISS（`IndexFlatIP` 内积索引，向量归一化后内积即余弦）。
- **表格库**：结构化表格存入 MongoDB，按"公司名称 / 财年年份 / 指标类别"建组合索引，支持精确匹配和跨表格关联。
- **知识图谱**：把四元组用 NetworkX 组装成图，导出 CSV 后导入 Neo4j，实体=公司与指标，关系=时间维度的数值属性，支持多跳查询。

*混合检索模块*
- 四级流程：**元数据过滤**（按公司、财年、报表类型先筛一遍）→ **三路召回**（`rank_bm25` 关键词检索负责专业术语精确匹配 ＋ FAISS 语义向量匹配 ＋ 知识图谱精确数值，BM25 权重 0.4 / 向量权重 0.6，含数字类问题自动切 0.5/0.5）→ **加权融合**（含查询同义词扩展、公司源过滤、图谱置顶）→ **BGE Reranker 重排**取 Top-5。
- **表格元数据增强检索**：把表格的行列标题、指标类型也拿来参与检索，提升"表格型"问题的定位精度。
- **知识图谱辅助**：对涉及多实体关系的问题（如"比较 A、B 公司毛利率趋势"），在图谱里找关联路径，把检索结果改写增强。

*程序辅助生成模块*
- **意图分类**：用少样本提示把问题分为事实型 / 数值计算型 / 对比推理型三类。
- **PAL（程序辅助生成）**：对计算型问题（如"算 2019 年流动比率"），引导大模型生成一段 Python 代码，丢进**安全沙箱执行**拿结果——而不是让模型心算（心算必错）。
- **多阶段校验**：事实一致性（生成片段 vs 检索片段比对）、逻辑连贯性、数值准确性（计算结果复核），三层过滤降幻觉。
- **溯源报告**：每个答案附带来源文档、页码、段落位置、检索推理路径，全链路可追溯。

*系统实现*
- 前端：Gradio，支持文档上传解析、问答、溯源证据查看、表格可视化、知识库管理（查询历史与收藏）。
- 后端：FastAPI 封装"解析 → 知识库 → 检索 → 生成"各模块，提供 RESTful API。
- 模型：默认走 DeepSeek API（deepseek-chat），内置 Qwen2.5-1.5B-Instruct 4-bit 量化本地模型兜底（API 不可用或数据不出内网时切换）；数据来自上市公司年报（2019–2021），云端 4346 份 / 本机 20 份开发。

**我的职责**：全流程独立实现——从数据准备、知识库构建、检索与重排、PAL 生成、前后端到评估。

**成果**：构建 100+ 条金融问答对（事实 / 计算 / 对比三类）做评测闭环，所有答案附带可验证引用来源与溯源报告，秒级响应，满足金融场景对可解释性与可追溯性的要求。

### 2. 生产制造工厂工时管理系统

**技术栈**：Vue 3、Spring Boot、MySQL、MyBatis、AliyunOSS、Nginx

**背景**：工厂工时统计原先靠纸质工时单 + 人工汇总，上报易出错、统计口径不统一、管理者拿不到实时数据。

**具体做了什么**：

- **数据库设计**：设计用户 / 角色、图纸、工序、工时记录等核心表，梳理主外键与唯一约束，为高频查询（按项目、时间跨度聚合）建索引，并做查询与维护效率优化。
- **图纸管理**：图纸上传至阿里云 OSS，系统为每张图纸生成**二维码**（内容含图纸 ID + 工序 ID），贴到产线，工人扫码直达对应填报页。
- **工时上报**：扫码后按项目、工序、时间段填报工时，数据实时入库，替代纸质工时单。
- **工时统计模块**：实现按项目、时间跨度等维度对工时做 SQL 分组聚合，统计结果**一键导出 Excel**，供生产排期和成本核算用。
- **权限管理**：角色分级（工人 / 班组长 / 管理员），后端接口鉴权 + 前端按钮级控制。

**我的职责**：参与数据库表结构设计，完成核心表构建与优化；负责工时统计模块（数据汇总 + Excel 导出）；针对系统查询与维护效率做了专项优化。

**成果**：系统成功上线，实现图纸二维码、工时扫码上报、多维度统计与导出等核心功能，工时数据的实时性与准确性明显提升。

### 3. 端到端房价预测与模型部署

**技术栈**：Pandas、NumPy、scikit-learn、XGBoost、Matplotlib、Flask

**背景**：目标不是"训一个模型"，而是把「原始数据 → 可调用的模型 API」走成完整闭环。

**具体做了什么**：

- **清洗**：数值特征用中位数 / 类别特征用众数补缺失，处理异常值与重复样本。
- **特征工程**：用 Matplotlib/Seaborn 画相关性热力图与分布图辅助选特征；类别特征做编码；对偏态的目标变量做**对数变换**让模型更好拟合。
- **建模**：先用线性模型和决策树建立基线，再选用 **XGBoost** 构建堆叠集成模型（多模型加权融合）；用**交叉验证**统一评估，建立可复现的调参流程——每次改动跑同一套验证，用数字说话。
- **调参**：网格 + 随机搜索结合，把 RMSE 从基线逐步优化到 **0.0337**。
- **部署**：Flask 写 `POST /predict` 接口，加载训练好的模型权重，把特征预处理封装成与训练一致的管道，请求进来先转换再预测，返回 JSON，实现实时预测。

**沉淀**：数据质量决定上限、评估闭环保证每次改动可衡量、模型部署成服务才算真正落地。

### 4. 客户价值分析（RFM + K-Means）

**技术栈**：Pandas、NumPy、scikit-learn（K-Means）、Matplotlib

**背景**：电商场景营销资源有限，得先搞清楚谁是高价值客户，预算才花得准。

**具体做了什么**：

- **预处理**：剔除空订单、异常金额，时间字段统一标准化，按用户聚合出最近购买时间、购买频次、消费总额三个指标。
- **RFM 评分**：按分位数把 R / F / M 各映射到 1–5 分，得到每个用户的 RFM 三元评分；并设计了**动态权重算法**，根据业务消费特征调整三个维度权重，而不是套固定模板。
- **聚类分群**：对评分标准化后跑 **K-Means**，用肘部法则确定聚类数，对聚类结果做区分度验证。
- **业务解读**：给每个分群画像——高价值核心用户、潜力用户、流失风险用户，并计算各群的用户占比与营收贡献。

**成果**：精准识别出占总用户数 **15%** 的高价值群体，该群体贡献约 **60%** 的营收，并用 Matplotlib/Seaborn 输出可视化分析报告，为精准营销提供了数据支撑。
