## 三、部署方式（可复现）

全部封装成脚本，一条命令即可重复部署：

```powershell
cd D:\Desktop\myblog

# 首次：先授权部署公钥（会提示输一次服务器 root 密码）
powershell -ExecutionPolicy Bypass -File .deploy\authorize_key.ps1

# 完整部署（含前端构建；本地沙箱限制 esbuild 时用 -SkipBuild）
powershell -ExecutionPolicy Bypass -File deploy\deploy.ps1

# 只更新后端（前端没改，跳过构建）
powershell -ExecutionPolicy Bypass -File deploy\deploy.ps1 -SkipBuild
```

`deploy.ps1` 做的事：构建前端 → 打包（排除 `.git`/`node_modules`/模型/数据库）→ **MD5 校验上传** → 服务器初始化（仅首次）→ 装依赖 → `init-db` + `reindex` → 重启并自测。

服务器侧两个脚本：

| 脚本 | 作用 | 频率 |
|------|------|------|
| `deploy/server_setup.sh` | 装 `python3-venv`/`nginx`/`build-essential`、建 2 GiB swap、建 `blog` 用户、装 Nginx 站点与 systemd 单元 | 只跑一次 |
| `deploy/server_install_app.sh` | 解包代码 → 预置模型缓存 → 写 `.env`(600) → 建 venv → 装依赖 → 建索引 → 重启 | 每次部署 |

## 四、本次踩的坑与修复

### 1. `ctypes.wintypes` 在 Linux 上导入即崩溃

`backend/modules/security.py` 顶部 `import ctypes.wintypes`，该模块在非 Windows 平台会抛
`ValueError: _type_ 'v' not supported` —— 属于**导入期异常**，整个 Flask 应用都起不来。

**修复**：不再 import `wintypes`，`DWORD` 改用 `ctypes.c_uint32` 表达（ABI 等价）。
非 Windows 上 `encrypt_secret`/`decrypt_secret` 仍会明确抛 `RuntimeError`，
而 `get_api_key()` 会自动回退读取明文 `DEEPSEEK_API_KEY`。

> 因此服务器上用明文 Key（`chmod 600`），DPAPI 密文绑定 Windows 用户+机器，Linux 解不开。

### 2. chromadb 会在「当前工作目录」找 `.env`

以 `sudo -u blog` 执行 Python 时继承了 ssh 登录目录 `/root`，而 chromadb 初始化时
pydantic-settings 会 `stat('.env')`；`blog` 读不了 `/root`，于是抛的是
**`PermissionError` 而不是 `FileNotFoundError`**，把 `import chromadb` 直接炸掉。

**修复**：`server_install_app.sh` 里在跑任何 Python 之前 `cd "$APP_DIR"`，
并改用绝对路径调用 `manage.py`。

### 3. torch 默认拉 CUDA 版（+3~4 GB 无用依赖）

Linux 上 `pip install torch` 默认是 CUDA 构建，会连带 `nvidia-*` 3~4 GB；
官方 CPU 源 `download.pytorch.org` 在国内还经常超时（实测卡在 `download-r2.pytorch.org`）。
这台机器没显卡、内存又只有 1.6 GiB，必须用 CPU 轮子。

**修复**：从国内镜像的扁平 wheel 目录里动态挑选匹配当前 Python 的最新 CPU 轮子：

```
https://mirrors.aliyun.com/pytorch-wheels/cpu/     ← 实测可用
https://mirror.sjtu.edu.cn/pytorch-wheels/cpu/     ← 备用
```

实测：`torch-2.14.0+cpu-cp312` **196 MB / 83 秒**（对比 CUDA 版 3 GB+）。
仍有官方源 → PyPI 的两级降级兜底。

### 4. scp 会「静默失败」，以及 PowerShell 5.1 的假失败

- **scp 偶发返回 0 但文件没传过去** —— 曾导致服务器上跑的还是旧版安装脚本，
  排查了很久。**修复**：`Send-File` 每次上传后比对 MD5，不一致自动重试（最多 4 次）。
- **`$ErrorActionPreference='Stop'` + 原生程序 stderr** —— nginx 把正常的
  `configuration file ... syntax is ok` 写到 stderr，PowerShell 5.1 将其包装成
  ErrorRecord 并当成终止错误，导致部署**在 nginx 重载那步中断、应用根本没重启**。
  **修复**：调用原生程序时临时切到 `Continue`，改由 `$LASTEXITCODE` 判成败。
- 本机只有 **Windows PowerShell 5.1**（没有 `pwsh`），且 5.1 读无 BOM 的 UTF-8 脚本会乱码，
  所以 `deploy.ps1` 保存为 **UTF-8 with BOM**。

### 5. 前端 URL 令牌自动登录失效（顺带发现）

Vue 的子组件 `onMounted` **先于**父组件执行，而 `App.vue` 是在自己的 `onMounted`
里读 `?owner_token=` 的 —— 带令牌打开 `/admin` 时，Admin 挂载那一刻 token 还是空的，
不会去拉数据，页面渲染成空仪表盘。

**修复**：把 URL 令牌的读取提到 `frontend/src/store/owner.js` 的**模块加载时**
（早于任何组件挂载），并顺手把写在 `?` 查询串里的令牌也从地址栏抹掉
（hash 里那份仍由 `App.vue` 用 `router.replace` 清理，不会进服务器日志）。

## 五、新增功能：每日 API 花费限额

公网开放后最怕「有人刷聊天 = 账单失控」，所以加了按天封顶。

| 身份 | 入口 | 是否限额 |
|------|------|----------|
| 访客 | `POST /api/chat` | ✅ 默认 **1 元/天**，超了直接回绝且**不再调用 DeepSeek**（零成本） |
| 主人 | `POST /api/chat/owner` | ❌ **不受限**，但仍记账，方便查看自己花了多少 |

**实现**（新增 `backend/modules/quota/`）：

- `models.py` —— `usage_daily` 表，按「日期 + 身份」一天一行，累加请求数/token/花费
- `service.py` —— 三档单价折算成本 + 拦截判定 + 单例
  - 计价：缓存未命中输入 ¥2/百万、缓存命中输入 ¥0.5/百万、输出 ¥8/百万（可用环境变量覆盖）
  - 拦截点：`chat()` 在调用 DeepSeek **之前**判断访客额度，超限直接返回友好提示
    （响应带 `quota_exhausted: true`）
  - 主人豁免：`mode == "owner"` 只记账不拦截；记忆/人格判断的额外调用也计入 owner
- `backend/tests/test_quota.py` —— 8 项测试覆盖计价、累计、拦截、豁免、`usage` 为
  `None`/`dict` 的健壮性、单行聚合

**实测成本**：一次访客对话（输入 1299 / 输出 74 token）= **¥0.0032**
→ 1 元约等于 **300 次访客对话/天**。

**查看花费**：

```bash
curl -s http://127.0.0.1/api/admin/summary \
     -H "Authorization: Bearer <OWNER_SECRET>" | grep -A 20 '"quota"'
```
