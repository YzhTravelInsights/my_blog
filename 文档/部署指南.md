# 部署指南（阿里云 ECS · Ubuntu 24.04）

把本项目部署到阿里云 ECS：**Nginx 托管前端静态文件 + 反向代理 `/api` 到 Gunicorn 里的 Flask 后端**。

| 项目 | 值 |
|------|-----|
| 实例 | `iZ2ze8ql2cmmyoqo0jd6ihZ`（2 核 / 2 GiB / Ubuntu 24.04 / 40 GiB ESSD） |
| 公网 IP | `47.94.91.5` |
| 部署路径 | `/home/blog/my_blog` |
| 运行用户 | `blog`（非 root） |
| 访问地址 | `http://47.94.91.5/` |

---

## 一、整体架构

```
浏览器
  │  http://47.94.91.5/
  ▼
Nginx :80
  ├── /              → /home/blog/my_blog/frontend/dist   （Vue 静态文件）
  └── /api/          → http://127.0.0.1:5000              （反向代理）
                            │
                        Gunicorn（1 worker / 4 线程，systemd 管理，用户 blog）
                            │
                        Flask 应用（wsgi.py:app）
                        ├── SQLite  backend/data/blog.db
                        ├── Chroma  backend/data/chroma
                        └── 本地 embedding 模型  backend/models（离线，不联网）
```

## 二、一次性准备（人工）

### 1. 阿里云安全组放行 80 端口

控制台 → 实例 → 安全组 → 入方向 → 添加规则：

| 协议 | 端口 | 授权对象 | 说明 |
|------|------|----------|------|
| TCP | 80 | 0.0.0.0/0 | HTTP |
| TCP | 22 | 你的出口 IP（推荐） | SSH |

> 不加 80 规则的话，服务器本身跑得好好的，但外网访问会超时。

### 2. 让部署机免密登录服务器

本项目用一对专用密钥（`id_ed25519`，只用于这次部署），跑一次：

```powershell
pwsh -File .deploy\authorize_key.ps1
```

会提示输入服务器 root 密码，成功后即可免密。也可以手动执行：

```powershell
$pub = Get-Content .deploy\deploy_key.pub -Raw
ssh root@47.94.91.5 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo '$pub' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

### 3. 准备服务器环境变量

`.deploy/server.env`（已被 `.gitignore` 忽略，不进 Git）：

```ini
DEEPSEEK_API_KEY=sk-你的key
DEEPSEEK_BASE_URL=https://api.deepseek.com
FLASK_ENV=production
OWNER_SECRET=<openssl rand -hex 32>
ADMIN_KEY=<openssl rand -hex 32>

# 访客每天最多花多少元（0 = 不限制）；主人模式不受限
QUOTA_DAILY_CNY=1.0
DEEPSEEK_PRICE_INPUT_MISS=2.0
DEEPSEEK_PRICE_INPUT_HIT=0.5
DEEPSEEK_PRICE_OUTPUT=8.0
```

> **为什么是明文 Key？** 本地开发用 Windows DPAPI 加密（`DEEPSEEK_API_KEY_ENC`），
> 密文绑定 Windows 用户和机器，**Linux 服务器上解不开**。
> `backend/modules/security.py` 在非 Windows 平台会自动回退读取明文 `DEEPSEEK_API_KEY`，
> 因此服务器上用明文变量，靠文件权限（600 / 仅 blog 用户可读）保护。

## 三、一键部署

```powershell
# 完整部署（含前端构建、代码打包、上传、装依赖、重建索引、重启服务）
pwsh deploy/deploy.ps1

# 只更新后端（前端没改，省掉构建）
pwsh deploy/deploy.ps1 -SkipBuild

# 常用组合：改完文章/后端后重新部署
pwsh deploy/deploy.ps1 -SkipBuild
```

首次执行会自动完成两段：

1. **服务器初始化**（`deploy/server_setup.sh`，只跑一次）
   装 `python3-venv / nginx / build-essential`、建 **2 GiB swap**、建 `blog` 用户、
   装 Nginx 站点与 systemd 单元。
2. **应用部署**（`deploy/server_install_app.sh`，每次都跑）
   解包代码 → 预置模型缓存 → 写 `.env` → 建 venv → 装依赖 →
   `init-db` → `reindex` → 重启服务 → 自测 `curl`。

## 六、每日花费限额（访客封顶 1 元 / 主人豁免）

服务器上最怕的事是「公网开放 + 有人刷聊天 = 账单失控」。默认已经封顶：

| 身份 | 入口 | 是否限额 | 说明 |
|------|------|----------|------|
| 访客 | `POST /api/chat` | ✅ 默认 1 元/天 | 超了直接返回「今天聊太多啦」提示，**不再调用 DeepSeek**，成本为 0 |
| 主人 | `POST /api/chat/owner` | ❌ 不限额 | 仍会记账，方便你知道自己花了多少 |

**怎么看花了多少**

```bash
ssh root@47.94.91.5
# 用你的 OWNER_SECRET 调管理接口，看 system.quota
curl -s http://127.0.0.1/api/admin/summary \
     -H "Authorization: Bearer <OWNER_SECRET>" | python3 -m json.tool | grep -A 20 '"quota"'
```

返回里 `guest.spent_cny` 是今日访客花费，`guest.remaining_cny` 是剩余额度，`owner.spent_cny` 是你自己的花费。

**怎么调**

改 `/home/blog/my_blog/backend/.env` 里的 `QUOTA_DAILY_CNY`：

- 想放宽到 5 元/天 → `QUOTA_DAILY_CNY=5.0`
- 想关掉限额（风险自负）→ `QUOTA_DAILY_CNY=0`
- 官方调价了 → 同步改 `DEEPSEEK_PRICE_*` 三个单价

改完 `systemctl restart blog` 生效。

**数据落在哪**

`backend/data/blog.db` 的 `usage_daily` 表，按「日期 + 身份」一天一行，已随其它数据一起备份（见第五节备份命令）。

> 计价口径：记录 DeepSeek 返回的 `usage`，按「缓存未命中输入 / 缓存命中输入 / 输出」三档单价折算。
> 单价默认取 `deepseek-chat` 官方价（2 / 0.5 / 8 元每百万 token），换算后写入 `cost_cny`。

## 七、内存与性能说明（2 GiB 机器的取舍）

本地 embedding 模型（`all-MiniLM-L6-v2` + torch）是本项目最吃内存的部分：

| 组件 | 常驻内存 |
|------|----------|
| Gunicorn（1 worker，含 torch + 模型 + Chroma） | ~600–800 MiB |
| Nginx | ~20 MiB |
| 系统 | ~300 MiB |
| **合计** | **~1.1 GiB / 2 GiB** ✅（另有 2 GiB swap 兜底） |

因此刻意做了这些取舍：

- `workers = 1`：每多一个 worker 就多一份 torch 常驻内存，2 GiB 机器会被 OOM Kill。
- `worker_class = gthread` + `threads = 4`：用线程扛并发，聊天等慢请求不阻塞其它访客。
- `torch` 走 CPU 源（`download.pytorch.org/whl/cpu`）：默认源会拉 CUDA 版，多下 2 GB+ 且这机器没显卡。
- 2 GiB swap：模型加载瞬间的内存尖峰不至于触发 OOM。
- 模型缓存预先上传：`rag.py` 强制 `TRANSFORMERS_OFFLINE=1`，联网下载在国内必超时，且会让启动卡住。

## 八、后续可选升级

### 绑域名 + HTTPS

1. 域名 A 记录解析到 `47.94.91.5`，安全组放行 443；
2. `apt install certbot python3-certbot-nginx`；
3. `certbot --nginx -d your.domain.com`（会自动改写 `deploy/nginx-blog.conf` 对应的站点配置）；
4. 把 `deploy/nginx-blog.conf` 的 `server_name` 改成域名并重新 `pwsh deploy/deploy.ps1`。

> 国内服务器绑域名需先完成 **ICP 备案**，否则 80/443 会被拦截。
> 备案号可在 `frontend/src/config/site.js` 的 `icp.number` 里填写。

### 把密钥加密方案改成跨平台

若要避免服务器上出现明文 Key，可把 `modules/security.py` 的 DPAPI 换成
`cryptography.fernet.Fernet`，密钥放独立文件（600 权限），
这样 Windows / Linux 都能用同一套密文。当前实现已确保跨平台可运行（Linux 自动回退明文）。

## 九、故障排查

| 现象 | 排查 |
|------|------|
| 浏览器打不开，`curl 127.0.0.1` 正常 | 安全组没放行 80 端口 |
| 502 Bad Gateway | `systemctl status blog`；多为后端启动失败，看 `journalctl -u blog -n 100` |
| 后端启动很久 | 首次加载 torch 模型约 10–20 秒，属正常；`TimeoutStartSec=180` 已给足 |
| 服务反复重启 | 多半是 OOM：`dmesg \| grep -i kill`，确认 swap 生效 `free -h` |
| 聊天回复不引用文章 | 模型缓存缺失导致 RAG 降级：检查 `/home/blog/my_blog/backend/models`，重新 `deploy.ps1 -Force` |
| 日志里 Key 解密失败警告 | `.env` 里残留了 `DEEPSEEK_API_KEY_ENC`，Linux 上删掉它，改用明文 `DEEPSEEK_API_KEY` |
| `npm run build` 报 spawn EPERM | 本地沙箱限制，需放开子进程权限后重试 |
